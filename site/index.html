Zero dependencies

The compiler is Rust with no crates. It builds anywhere Rust does and writes plain, readable C and JavaScript.

One IR, two targets

Native code through C, and JavaScript for Node and the browser. Same output, same evaluation order, same runtime errors.

Fits in one prompt

The whole language is a short spec an agent reads in one go. The compiler corrects what is left.

Design

Every rule removes a way to be wrong.

Nyra is shaped by how language models write code, not by what humans like to read. Fewer choices, fewer wrong ones.

One obvious way

One spelling for each thing. No implicit conversions, no shadowing, no null: 1 + 2.0 is error E0210. A model that half-knows Rust, Go or TypeScript already knows the syntax.

No semicolons

A new line ends a statement. Braces are required and stay on the line that opens them. A stray ; is error E0005, and the hint says: delete it.

Errors are instructions

Every error has a stable code, an exact position and a hint that says what to write. --json is for agents, nyra explain E0201 is for the why.

Values, not references

Assigning, passing and returning always make independent values. Copies share storage until one side writes, so nothing changes behind an agent's back.

Memory: automatic, and yours to steer

Reference counting frees memory when the last owner is gone: no garbage collector, no borrow checker. free, keep and arena say exactly when.

The same output everywhere

Both backends come from one intermediate representation, so evaluation order, number formatting and runtime errors match byte for byte.

A stable code

Codes never change meaning. nyra explain E0230 prints what it means, why the rule exists, the usual causes, and a wrong and a fixed program.

An exact position

File, line and column, the same on both backends. Runtime errors carry them too, with "runtime":true in the JSON.

A hint that says what to write

Not "syntax error", but the line to type: a closest-name suggestion, the missing type, the keyword you meant.

Compiler

One source, one IR, two targets.

A small Rust compiler with zero dependencies. Both backends read the same typed intermediate representation, so a program prints the same thing whether it runs natively or on JavaScript.

Source. Plain text, written by an agent. Newlines end statements, so there are no semicolons.

fn sq(x: int) -> int = x * x

fn main() {
    print(sq(5))
}

Tokens. The lexer cuts the text into keywords, names, types and symbols.

fnsq(x:int)->int=x*xnewline

Tree. The parser builds a syntax tree. It recovers after an error, so one mistake does not hide the next.

Types. The checker gives every node a type and collects every error in one pass.

IR. One typed intermediate representation. Expressions are pure and every effect is its own statement, so the evaluation order is fixed once, for every backend.

fn sq(x: int) -> int {
    return (x * x)
}
fn main() {
    %0: int = call sq(5)
    print(%0)
}

Two backends. The same IR becomes C99 for gcc or clang, and JavaScript for Node or the browser.

C99 → native executable

static int64_t ny_sq(int64_t x) {
    return x * x;
}

JavaScript → Node, browser

function sq(x) {
    return x * x + 0;
}

The + 0 turns an int -0 into 0: C has no -0 for ints, so JavaScript may not print one either.

Output. Run it either way and the bytes are the same.

native
$ nyra run sq.nyra
25
JavaScript
$ nyra run sq.nyra --js
25
identical output

The IR above is the compiler's real dump for this program. Every example in the repository runs on both backends in CI and must match byte for byte.

Memory

Values, not references.

Copy a value and you get an independent value. Under the hood the copy is free until one side writes: then, and only then, the memory splits.

    var b = a
    b.push(3)
    a[0] = 9
    print(a)

[9, 2][1, 2, 3]

A value is an array of two numbers.

Automatic by default. Manual when you say so.

Reference counting frees memory the moment the last owner is gone, with no garbage collector and no pauses. When you want to be exact, three words say so, and the compiler checks them.

free(x)

Give the memory back now. Using x afterwards is a compile error (E0239), until you assign it a new value.

keep(x)

Mark a value as living for the whole program: it is never freed early.

arena { }

A block whose values are freed together at the closing brace. Values leave only through ret, and outer values are read-only inside. Version 0.3 checks these rules; a faster bulk allocator comes later.

Language · v0.3

Small enough to hold in your head.

Version 0.3 adds real data: strings and chars with methods, arrays, structs, inout parameters, break and continue, and explicit memory control. Every program below was compiled and run; the output is what the compiler printed, identical on native and JavaScript.

Functions with typed signatures, one-line functions, let and var, compound assignment, string interpolation and if as a value.

basics.nyra
fn add(a: int, b: int) -> int = a + b

fn gcd(a: int, b: int) -> int {
    if b == 0 { ret a }
    ret gcd(b, a % b)
}

fn main() {
    let x = 5
    var total = 0
    total += add(x, 2)
    let size = if total > 6 { "big" } else { "small" }
    print("total {total} is {size}")
    print("gcd(48, 18) = {gcd(48, 18)}")
}

Structs have named fields and are built like a call: User(name: "ann", age: 30). They are values too.

    age: int

fn older(u: User) -> User = User(name: u.name, age: u.age + 1)

fn main() {

    print(ann)
    print(next)
}

A function can change the caller's variable, and the call says so with inout. Two inout arguments are never the same variable.

inout.nyra
fn swap(inout a: int, inout b: int) {
    let t = a
    a = b
    b = t
}

fn main() {
    var x = 1
    var y = 2
    swap(inout x, inout y)
    print("{x} {y}")
}
outputnative = JS
2 1

Memory is automatic. free, keep and arena change only when it is returned, never what the program prints.

memory.nyra
fn longest_word(text: str) -> str {
    arena {
        let words = text.split(" ")
        var best = ""
        for w in words {
            if w.len() > best.len() { best = w }
        }
        ret best
    }
}

fn main() {
    var big = [0].repeat(100000)
    print(big.len())
    free(big)
    big = [1, 2, 3]
    let table = [1, 4, 9, 16]
    keep(table)
    print(longest_word("the quick brown fox"))
    print(big)
    print(table)
}

For agents

Point a model at the repo. It does the rest.

Nyra is brand new, so no model has seen it in training. It does not need to: the docs are short enough to read in one go, and the compiler corrects what is left.

prompt

Read https://github.com/SpAkXD/nyra, starting with llms.txt and docs/AI_GUIDE.md, then write me a Nyra program that prints the first 20 prime numbers.

  • llms.txtWhat Nyra is, the ten most important rules, links.
  • AI_GUIDE.mdWorkflow, do and don't rules, error codes with fixes, complete programs.
  • SPEC.mdThe complete language spec.
  • ERRORS.mdEvery error code: what it means, why, causes, a wrong and a fixed program.
  • examples/Runnable programs, each with its expected output in a .out file.

Get started

Install, then run.

One binary: nyra. Native programs need a C compiler (gcc, clang or tcc, found automatically). The JavaScript backend needs Node.js instead.

Prebuilt binary

Linux x86_64, Windows x86_64 and macOS Apple Silicon. Download the archive from the latest release, unpack it and put nyra on your PATH.

Latest release

On macOS run xattr -d com.apple.quarantine nyra once: the binary is not signed.

From source

Any platform with Rust.

shell
git clone https://github.com/SpAkXD/nyra
cd nyra
cargo build --release

The binary is target/release/nyra. Or: cargo install --git https://github.com/SpAkXD/nyra

Your first program

hello.nyra
fn main() {
    print("hello from nyra")
}

Save it as hello.nyra, then:

shell
nyra run hello.nyra
nyra run hello.nyra --js
nyra run hello.nyraCompile and run natively.
nyra run hello.nyra --jsThe same program on Node.js.
nyra build app.nyraA native executable next to the source. Unchanged programs skip the C compiler.
nyra check app.nyra --jsonOnly report errors, as JSON for agents. Exit code 0 means no errors.
nyra explain E0230What an error means, why, the usual causes, a wrong and a fixed program.

Options

--jsuse the JavaScript backend
--cwith build: write the generated C
-o <path>output path for build
--jsonerrors as JSON, compile and runtime
--timeshow how long each step took

Exit codes

0success
1compile errors
2usage or tool problem
101runtime error, identical on both backends

Roadmap

Small versions, each one tested on every backend.

Nyra is 0.x, so the syntax may still change before 1.0.

  1. v0.1 Core done

    Functions, int float bool str, if, while, for, the C and JavaScript backends, JSON errors.

  2. v0.2 Short code released

    One-line functions, +=, string interpolation, if as a value, a build cache, runtime errors, and a typed IR under both backends.

  3. v0.3 Real data now

    Strings and chars, arrays, structs, inout, break and continue, reference counting with free, keep and arena.

  4. v0.4 The proof harness ready

    The benchmark: first-try correctness and code length against Python, TypeScript and Rust. Results coming.

  5. v0.5 More targets planned

    A WebAssembly backend and a browser playground that runs the compiler itself.

  6. v0.6 Big programs planned

    Modules and imports, a standard library, and a C foreign function interface.

  7. v1.0 Ecosystem planned

    Packages and addons, a published VS Code extension, a docs site.

Open source
